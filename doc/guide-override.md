# Overrides

**Owns.** The decisions that are true for this project only, and that outrank the general principles
for as long as they hold.

**Not here.** The principles themselves — [guide-general.md](guide-general.md) is written to outlive
this project, which is exactly why its exceptions are kept here rather than folded into it. If
something is permanent it is not an override, and it belongs there.

**Every override names what it outranks and what would end it.** An override with no stated expiry
never gets removed, because nobody can tell whether it still applies — and a stale override is worse
than a missing principle, since it goes on reading as authority.

**This file is meant to be deleted.** When the last override ends, the file goes with it. That is the
difference between recording an exception and quietly rewriting the rule.

---

## O-1 · The routine is the product; the project is the vehicle

Trazer exists to develop a way of working with an AI agent. The game is what gives that way of working
something real to fail against — a project with no artefact teaches nothing, because nothing can be
wrong.

When the two pull in different directions, the routine wins: a lesson written down is worth more than
a level shipped.

**Outranks.** *Say what a person can do that they could not before.* Here a goal that delivers nothing
to a player can still be the right goal, provided it teaches the routine something. Without this
override, that bullet rules out most of what this project exists to do.

**Costs.** Features get cut for reasons that have nothing to do with the game being better, and time
goes into writing documents when it could go into playing. That is the deal, not a disappointment.

**Ends when.** This project stops being a practice vehicle and becomes a game somebody plays. At that
point delete this override rather than softening it — a half-held override is exactly the stale kind
described above.
